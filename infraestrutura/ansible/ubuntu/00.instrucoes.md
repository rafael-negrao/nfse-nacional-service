# Instruções de Operação — Biblioteca NFS-e Nacional

## O que "deploy" significa aqui

Este repositório é uma **biblioteca**, não uma aplicação. Não há jar para publicar, serviço
`systemd` para reiniciar nem porta para expor. O deploy consiste em atualizar o código no servidor
e rodar `mvn clean install`, deixando os três artefatos no **repositório Maven local do
`app_user`**:

```
~/.m2/repository/br/com/adelfo/nfse/nacional/
├── nfse-nacional-schemas/1.0.0/
├── nfse-nacional-client/1.0.0/
└── nfse-nacional-service/1.0.0/
```

É de lá que o [`cms-root`](../../../../cms-root/infraestrutura/ansible/ubuntu/00.instrucoes.md) os
resolve quando roda o próprio `03.ci.sh`.

> **Ordem obrigatória:** esta biblioteca **antes**, a aplicação consumidora **depois**. Invertida,
> o build do cms-root falha por dependência não resolvida.

```shell
# 1. biblioteca
cd nfse-nacional-service/infraestrutura/ansible/ubuntu && ./03.ci.sh --ambiente prd_comaho

# 2. aplicação
cd ../../../../cms-root/infraestrutura/ansible/ubuntu && ./03.ci.sh --ambiente prd_comaho
```

Como não há serviço nesta biblioteca, os scripts de restart, stop e status **não existem aqui** —
eles pertencem à infraestrutura da aplicação que a consome.

## Pré-requisitos

- `terraform` e `ansible-playbook` no PATH
- Terraform do **cms-root** aplicado em `../../../../cms-root/infraestrutura/terraform/`
- Chaves PEM presentes em `<terraform>/ec2_instance/`
- Arquivo de variáveis do ambiente criado (ver abaixo)

Os IPs vêm do Terraform do cms-root — esta biblioteca não provisiona máquina nenhuma:

```shell
cd ../../../../cms-root/infraestrutura/terraform && terraform output
```

## Arquivos de variáveis — não versionados

Os `*_vars_file.yml` carregam o **token do GitHub** e por isso **não entram no repositório**. Cada
ambiente tem um `.example` versionado; copie e preencha:

```shell
cp comaho_prd_vars_file.yml.example comaho_prd_vars_file.yml
$EDITOR comaho_prd_vars_file.yml     # preencher github_token
```

| Ambiente do script | Arquivo de variáveis |
|---|---|
| `hlg_comaho` | `comaho_hlg_vars_file.yml` |
| `prd_comaho` | `comaho_prd_vars_file.yml` |
| `prd_mcamas` | `mcamas_prd_vars_file.yml` |

> **Divergência deliberada em relação às outras infraestruturas.** O `nfe-sefaz-sp` e o `cms-root`
> versionam esses arquivos com segredos em texto claro. Aqui não: este repositório está hospedado
> no GitHub, e um token commitado é detectado e revogado pelo próprio secret scanning — além de
> ficar no histórico para sempre. Os scripts recusam rodar se o arquivo não existir, com instrução
> de como criá-lo.

## Ambientes

Todos os scripts aceitam `--ambiente` com um ou mais valores. O padrão é `hlg_comaho`.

| Valor | Descrição | Output Terraform |
|---|---|---|
| `hlg_comaho` | Homologação Comaho (`hml_comaho` também vale) | `hlg_comaho_ec2_public_ip` |
| `prd_comaho` | Produção Comaho | `prd_comaho_ec2_public_ip` |
| `prd_mcamas` | Produção MCamas | `prd_mcamas_ec2_public_ip` |
| `all` | Todos os três | — |

```shell
./03.ci.sh                                    # default: hlg_comaho
./03.ci.sh --ambiente prd_comaho              # um ambiente
./03.ci.sh --ambiente prd_comaho prd_mcamas   # múltiplos
./03.ci.sh --ambiente all                     # todos
```

## Scripts

### 03 — CI: Git Pull + Instalação no `~/.m2`

> Script: [`03.ci.sh`](03.ci.sh) · Playbook: [`03.ci/03.01.git_pull_maven_build.yml`](03.ci/03.01.git_pull_maven_build.yml)

Clona ou atualiza o repositório no servidor e roda `mvn clean install`.

```shell
./03.ci.sh --ambiente prd_comaho
./03.ci.sh --ambiente all --pular-testes
```

O playbook faz três coisas que valem menção:

- **Exige Java 21 antes de começar.** Sem isso o Maven falha na compilação com uma mensagem sobre
  `release 21` que não deixa claro que o problema é a JDK do servidor;
- **cria um swapfile de 2 GB** se ainda não houver, e limita o heap do Maven a 1 GB. O `xjc` gera
  117 classes e o build multi-módulo derruba VMs pequenas por OOM — lição herdada do `cms-root`;
- **confere que os três artefatos chegaram ao `~/.m2`** e falha se não chegaram. Um build verde que
  não instalou nada passaria despercebido, e o erro só apareceria no build da aplicação.

Os **132 testes rodam por padrão**: são offline, levam segundos e validam os documentos contra os
XSDs oficiais. `--pular-testes` existe para deploy urgente, não para uso rotineiro.

## Primeira instalação num servidor novo

```shell
cp comaho_prd_vars_file.yml.example comaho_prd_vars_file.yml && $EDITOR comaho_prd_vars_file.yml
./11.setup.java21.sh --ambiente prd_comaho
./03.ci.sh          --ambiente prd_comaho
```

Depois, o deploy da aplicação consumidora.
